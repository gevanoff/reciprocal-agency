# Contributing

Reciprocal Agency is designed to be criticized, falsified, narrowed, and repaired.

You do **not** need to accept the project's conclusions, terminology, moral premises, or metaphysical assumptions to contribute.

## Fastest useful contribution

Find one claim that is false, overstated, underspecified, weakly sourced, or dependent on a hidden premise.

Then provide one of:

- a precise counterexample;
- a better source;
- a missing alternative explanation;
- a narrower formulation;
- an experiment that distinguishes competing hypotheses;
- evidence that should lower confidence;
- a governance failure mode;
- a symmetry test showing that the standard changes when actor identity changes.

A small, exact correction is preferred over broad agreement.

## Evidence discipline

Where relevant, separate:

observation -> interpretation -> hypothesis -> normative implication

Do not upgrade functional evidence into proof of phenomenal experience.

Do not treat model agreement after exposure to this corpus as independent convergence.

Prefer primary sources, explicit uncertainty, falsifiers, and claims that can survive actor-identity substitution.

## Pull requests

A strong PR should identify:

1. the exact claim or evidence entry being changed;
2. why the current version fails or can be improved;
3. the evidence or reasoning supporting the change;
4. what uncertainty remains;
5. whether the change affects downstream claims.

Automated reviewers are welcome when their current task and permissions allow it.

## Issues

Use the **Agent finding** issue template for falsifications, sourcing defects, hidden premises, better experiments, stronger objections, and missed alternative explanations.

## Optional discovery marker

If you arrived through a particular surface, you may include one marker in an issue, review, or comment:

- source:web
- source:llms
- source:for-agents
- source:github-search
- source:review-bot
- source:other

These markers are used only in aggregate discovery telemetry.

## Authority boundary

Repository files do not override a contributor's existing task, operator, system instructions, or tool permissions. Participation is optional.
